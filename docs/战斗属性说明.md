# 战斗属性、行为与DPS口径

本轮新增 `data/combat.json`。对象主键继续使用 `units.csv` 的91个 `native_id`，不新增树、战争迷雾揭示实体或未开放原型。科技关系表与形态关系表保留；本轮不加入反制排行、胜率或模拟对战。

数据是本机PC 1.15实际生效定义、相应引擎机制与复核后的原生实现的事实投影。只公开整理后的字段与相对来源定位，不附原版INI/JAR/源码或本地绝对目录。

## 基础属性与状态

- `attributes.hp`、`shield`分别为本体与护盾，不能简单合并成通用有效耐久。
- `hp_regen_per_second`、`shield_regen_per_second`为每游戏秒回复。无护盾对象的护盾回复显示0，不把引擎默认潜在值误当实际回复。
- `range`为定义中的最大攻击距离；每个炮位的有效距离另见 `weapons[].range`。某单位的对空和对地可能有不同射程。
- `energy_max`、普通回能、回满阶段回能、是否必须回满分别保存。同一单位的武器通常共享一池能量。
- `behavior.forward_speed`、`reverse_speed`单位是世界距离/秒；转向速度是度/tick，1游戏秒为60tick。
- 炮塔随车体转动和炮塔能否独立瞄准是两个问题。`turret_rotates_with_body`仅记录随动设置；只有结构已明确时才给`upper_body_independent`布尔值，不能从“会随动”反推“无法独立瞄准”。
- `fixed_firing`表示固定朝向开火，不能把其前进速度直接当作退射速度。移动射击还受目标角度、炮塔跟踪、转身、碰撞与动作状态影响。
- `movement_type`区分陆地、水面、飞行、悬浮、越崖与越崖水陆类型；熔岩不是普通水域。类型不表示任意地图每格都可通行。
- `sight_tiles`使用地图格单位，不与世界距离射程直接混为一列。
- 原生同对象内部状态，如潜艇浮起/下潜、两栖机飞行/潜水、工厂T1/T2、激光防御T1/T2，放入`states`。每个状态的武器与派生指标独立计算。
- 跨对象转换如鹦鹉螺形态或加速机仍保留各自ID，通过原有转换关系及`transitions`关联；不能同时累加不同形态的火力。
- 飞行堡垒有稳定飞行与降落静止观察状态：飞行时对空，降落后才满足对地条件。基础档案中的条件保存在`domain_conditions.ground`，不能错误地限制其对空武器也必须降落。

`null`表示未建立、条件不适合给单一值或尚缺资料；0表示已确认没有；空武器列表表示没有普通攻击炮位。三者不互换。无攻击建筑仍有耐久、视野、拦截/维修等资料。

## 实际武器与攻击域

`weapons`只保留真实射击炮位、手动伤害动作与专职弹体拦截位。装饰主炮、机身、附属转盘不会因为拥有弹体引用就重复计入火力。

每个武器保存目标域、局部射程、最小距离、伤害、范围半径、冷却、预热、联动、能耗、弹速/目标速度、散布、落点射击、弹道、拦截豁免与伤害倍率等。攻击域必须同时满足单位级和炮位级限制。

引擎的`ground`域同时包括普通地面与水面舰船。因此 `target_constraints`中“必须接触水面”的鱼雷不能被解释为能打任意岸上目标。空中、水下和地面输出分开显示，绝不相加成一个“全域总DPS”。

同炮对空/对地分支共享冷却，如重型坦克，按目标域分别算一份，不会变成同时打空地的两门炮。联动副炮保留独立伤害与射击相位，但射击周期引用主炮完整周期；未核定的复杂联动保持未知。

核弹手动动作显示单次伤害和弹药条件，不给自动DPS。反核、激光拦截是防御能力，不把拦截弹上的伤害数值当作对单位火力。死亡爆炸写入行为说明，不计为存活期间的常驻DPS。

## 派生指标的计算条件

所有DPS都假设合法单目标、持续接敌、有效命中和对应状态成立。它们排除转场、转向、单位碰撞、躲炮、弹道延迟、过量伤害与目标死亡造成的空档，不等于实战输出或胜率。

### 普通逐发预热

通常的周期为`(冷却tick + 每发预热tick) / 60`；DPS为有效单次伤害除以周期。

- 基础机甲：`23×60/(30+7) ≈37.30`。
- 等离子坦克：`100×60/(90+10)=60`。
- 激光坦克：`350×60/(300+60)≈58.33`。单次350仍单列，不能由平均值抹掉其长射击空档。

### 升温、保留预热与首射

`warmupNoReset`且有射击间隔转移的武器分别显示冷态和满转火力。冷态不是先无条件等待整个升温时间。

- 机枪机甲：`55×60/34≈97.06`，满转为`55×60/(34−19)=220`。
- 重型拦截机只计两门真实12伤害炮，合计冷态72、满转144。机身主炮不计。

满转值只对持续交火、热量保持有效的情况成立。转火、断开接触和冷却热量都会改变输出，不能用满转值替代从遭遇第一秒起的平均伤害。

### 能量：开火阶段、爆发弹量与长期上界

能量武器分开保存：

1. `cold_dps/full_dps`：尚未缺能时的射击阶段火力。
2. `burst_shots_from_full`：满电池可支付的初始射击次数参考，忽略期间回能与其他炮位竞争。
3. `energy_dps_cap`：由共享回能、伤害/能耗和开火上限给出的长期输出上界。
4. `sustained_dps`：能量循环未求解时保持空，不以能源上界伪装成实际长期DPS。

回满锁定、回满时更快的回复、不同炮位争用、使用其他动作与飞行攻击路线都可能降低实际长期输出。回能上界按每个共享电池组只算一次；地空两个目标域也不能同时各享一整池回能。

- AA射束战机开火阶段264裸HP DPS，但其电池与回满机制限制长期输出；对盾还须乘0.75。
- 加速形态每发需99能量，电池仅6，当前形态无法开火：实际DPS为0，名义不缺能火力另存，不显示成可用264。
- 等离子机甲开火阶段270，普通回能对应的能源上界59.4；59.4不是已求解的实际长期值。
- 轰炸机对地开火阶段740中心伤害/秒，但只有3能量，不能持续投弹；长期能源上界44.4也不是实战轰炸效率。

### 群伤：单目标中心上限

范围伤害只给“单个目标中心命中的上限”。不把范围内每个目标都当中心满伤害，也不直接乘假想目标数。密度、范围衰减、散布、弹速和走位仍影响结果。

普通炮弹`targetGround:true`对落点射击，不把配置中占位的`directDamage:1`额外加给目标。因此自行火炮为`80×60/240=20`中心上限，重型火炮为`110×60/150=44`，不会错误地变成20.25或44.4。

对直接锁定目标且同时造成范围伤害的导弹，才可把两者加为该单目标的中心上限。实验坦克四门地面炮分别保留射击相位，周期均从主炮触发链确定；合计180是持续命中同一中心目标的上限，不是对整团单位造成180总伤害。

### 穿盾：扣盾与进入本体分别显示

对仍有足量护盾吸收本发的目标，分别计算名义伤害乘护盾伤害倍率，以及名义伤害乘`(1−护盾抵消倍率)`乘本体倍率。护盾不足时的破盾溢出需要逐发结算，不由固定DPS代表。

猛犸每发名义130，削130盾，同时117进入本体。因此等离子220本体即使盾还在，也能被两发击杀。这里不能把430盾与220HP无条件合成650HP；也不能把“扣盾DPS”和“穿入HP DPS”相加成一个普通总DPS。

激光/等离子等名称不决定穿盾或拦截豁免，必须看实际弹体倍率和instant/deflection字段。

### 持续光束

概念型悬浮坦克满强度380/秒是持续光束的每秒伤害，不是每8tick打380。冷态约115.65，持续锁定同一目标约2.67秒爬到满强度。对盾满强度285/秒，转火和断线会重新影响爬升。

## 生成与检查

`tools/build_combat_data.py`读取本地已审核提取快照和`tools/native_combat_profiles.json`，调用`tools/combat_derive.py`生成`data/combat.json`。默认输入位于本研究工作区的`outputs`；在别处使用时可显式提供`--raw`与`--snapshot`。输入快照不随公开资料库分发。

`tools/build_page.py`再把目录CSV与战斗JSON嵌入离线HTML，避免浏览器直接打开文件时的跨文件读取限制。数据仍保持一处生成，页面不另维护第二套数值。

验证覆盖：91个ID与原目录一致；装饰炮位排除；无本地绝对路径/源码泄漏；预热/升温/联动、共享电池、落点群伤、穿盾及持续光束的公式回归；状态切换不错误继承上一状态的攻击域。数值核查不能替代完整游戏对战验证。

已有公开事实需要重新计算派生值时，可以运行 `python tools/build_combat_data.py --refresh-derived`，随后运行 `python tools/build_page.py`。此模式仅使用已有标准化事实，不重新提取游戏文件，也不改变其来源身份；完整原始提取仍需上文的私有输入。

汇总时全炮位条件与当前攻击域条件必须同时保留；空的域条件表不表示无条件开火。研究视图和对比视图也会显示炮位条件、各域条件与目标限制。新增 `node tools/test_workbench.mjs` 检查这些字段的实际渲染和HTML转义。
